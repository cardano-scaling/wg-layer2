## Meeting notes

- Recap from last time  https://github.com/cardano-scaling/wg-layer2/blob/main/meetings/2025-08-13.md

- Agenda collection

- Franco: Hydra use cases. Some about lots of transactions, some are about big UTxO sets. Which are the most important?
  - Tension between ledger size and confirmation times
  - Supply chain: values arbitrary data size more than low latency (can be up to 5 seconds)
  - Payments: should be less than a second, more confined domain
- Hydra in the payments use case (catalyst project of tudor)
  - How is it structured? one head having all users, or many small heads? 
  - Fast finality is essential
  - Heads operated by a small set of operators
  - UTxO state in that head for each payment system user

- Using a payment channel network would be much better in many aspects!
  - However, having a working product in the field with a subpar backend is valuable too.
  
- Discussed synchrony assumptions of payment channel networks / routing of payments using HTLCs
  - Related to cross-chain communication
  - Needs to factor in timeliness of action on involved systems
  - For example: need to be able to reveal secret ourselves within time of learning the secret along the HTLC path (to not lose collateral) 
  - Sebastian called out similarity with cross-chain communication. Interesting read about it: https://eprint.iacr.org/2019/1128
  
- Elaine: chair of the OSC now
  - Maintainer/retainer program
  - Paid program through the OSC budget
  - Opportunity for Cardano OS projects to pay maintainers
  - Deadline: October 13th
  - Not to replace maintainers, but rather supplement maintenance!
  - Hydra yes, Sebastian (or other IO contributors) may not be the best candidates as there is budget already available. However, contributors / builders using Hydra through catalyst projects are prime candidates!
